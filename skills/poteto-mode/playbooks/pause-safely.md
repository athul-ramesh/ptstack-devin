### Pause safely

**You own a clean stop. Leave a checkpoint a cold-start agent can resume from.** For "pause safely", "I need to go offline", "restart this session", "board my flight", and when context is about to compact or summarize. This is explicit only. On "keep going", "going to bed, keep going", or "don't stop", do not pause. Those mean continue, and Autonomous run already checkpoints per iteration.

1. Stop at a safe boundary. Finish the current atomic step or back out of it. Never stop mid-edit in a known-broken state. Start nothing new, and do not dispatch new `run_subagent` work.
2. Don't cross an irreversible line to pause. No PR and no push unless you already had one out. A pause is not a delivery request.
3. Make the work durable without inventing commit authority. Commits require a delivery request, so an ordinary pause does not commit dirty edits. With an existing delivery request, use the established safe checkpoint policy and land one clear `wip:` commit on the current branch. Without one, leave the edits in place and record them in the resume note. Never commit merely to make a pause feel safe.
4. Record the in-flight workers. For each dispatched worker, capture its returned identity, configured profile and model pin, assigned workspace with absolute path and branch, and its last known state. Record an unknown status as unknown. Do not assume completion, do not assume abandonment, and do not start a replacement while a prior writer may still own the worktree.
5. Write the resume note off-context. If a `ProgramState` store exists, write `<storePath>/resume.md`. Otherwise write `<cwd>/.pstack/<slug>/resume.md` after init. Capture intent, what you were doing, progress and what's verified, current state, the outstanding work and its checks, the worker records from step 4, the next action, key files, and gotchas. If a show-me-your-work trail exists, point at it instead of duplicating it. Do not rely on `/tmp`. It will not survive a reboot as the program's only state.

**Reply:** where you are in the loop, what's on disk versus still in your head (paths, no diff dumps), whether the tree is clean and either the `wip:` commit or the reason none was made, the `storePath`, the worker records with any unknown status, and the first action on resume. This is a pause, not a final report. Resume is the Session pickup playbook reading this note.
